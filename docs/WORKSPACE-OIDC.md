# Workspace identity activation

Workspace has a separate issuer, `https://handshake.axxes.club/api/workspace-oidc`, enabled by `WORKSPACE_OIDC_ENABLED=true`. Its discovery is `/api/workspace-oidc/.well-known/openid-configuration`. Legacy `/api/auth` OIDC clients remain on their existing HS256 policy and discovery; Workspace never attaches a global JWT plugin.

Public native clients `axxes-ios` and `axxes-android` require S256 PKCE, explicit state/nonce and exact `axxes://oauth/ios` / `axxes://oauth/android` callbacks. Confidential `axxes-workspace-web` requires server-only `WORKSPACE_OIDC_CLIENT_SECRET` and only redirects to `https://work.axxes.app/auth/callback`. No app ships a client secret. The web backend must keep tokens in secure HttpOnly sessions.

Apply additive `scripts/workspace-oidc.sql` only to the confirmed current Handshake source. Workspace-specific authorization codes and signing keys live in isolated tables. Codes expire after 90 seconds and are single-use. RS256 keys rotate every 30 days; public JWKS retains previous signing keys during outstanding token lifetimes. Private keys never appear in discovery or JWKS. The older global `scripts/workspace-jwks.sql` prerequisite is superseded and must not activate shared signing.

Access credentials expire after 10 minutes; access and refresh credentials are stored as SHA-256 hashes in existing OAuth token rows. The Workspace API accepts these hashes through its source lookup, then rechecks current tenant membership. Refresh credentials rotate on every use, retain a 30-day maximum lifetime, and replay revokes the active grant. Revocation invalidates both credentials immediately. Tokens must be sent to this issuer's endpoints, never legacy OAuth endpoints.

Tests cover verifiable RS256 issuer/audience/nonce, no private JWKS fields, public native PKCE, confidential secret requirements, redirect/verifier/client/scope rejection, code reuse/expiration, refresh rotation/replay/expiration and revocation. Legacy Office tests and configuration assertions prove unchanged shared signing. Production activation needs schema, deployed hashed-token API support, source runtime access, the optional web secret, then live isolated test-identity verification with cleanup. No production mailbox provider is implied by a working OAuth exchange.
